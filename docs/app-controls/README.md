# App 面板控制

App 的「功能」页按图标分组展示面板控制，默认收起；样式选项通过带设备截图预览的底部弹窗选择，列表显示名称而非枚举数字；数值在紧凑底部弹窗编辑，关闭时丢弃未提交的输入。普通操作在列表直接执行，危险操作弹窗确认。设置页采用设备概览、连接分组与系统信息卡片，连接、设备配置和更新表单点击标题展开；首页快捷卡片会自动打开对应分组。默认中文，语言沿用设备设置。需要配套固件提供 `/api/controls`，旧固件会明确提示读取失败。

| 功能 | App 入口 / 传输 |
|---|---|
| 亮度、音量、方向、单位、速度来源、语言、保护板和控制器型号 | 设备设置；HTTP / BLE，按固件清单显示 |
| 仪表样式、开机动画、满电续航、轮胎尺寸、传动比 | 面板功能控制；HTTP / BLE |
| 控制器连接开关、扫描，保护板断开 | 面板功能控制；HTTP / BLE |
| 热点开关、蓝牙广播、媒体按键 | 面板功能控制；HTTP / BLE，按编译模块显示 |
| 仪表/设置/快捷菜单切换、调节条位置 | 面板功能控制；HTTP / BLE |
| 触屏校准开始/取消 | 面板功能控制；HTTP / BLE；目标点必须在实屏点击 |
| 恢复默认 | 面板功能控制；HTTP / BLE；先确认 |
| 蚂蚁通道、蓝宝六位配对码 | 面板功能控制；HTTP / BLE |
| 保护板和控制器扫描、候选列表及 MAC 绑定 | 设备设置；HTTP |
| 热点密码修改 | Wi-Fi 设置；HTTP；保留八位数字规则 |
| GPS 辅助数据注入 | 面板功能控制；HTTP；单帧 CASBIN 文件，固件校验内容 |
| 轨迹、骑行历史、OTA、投屏 | 沿用已有 App 入口与传输要求 |

远程控制使用明确的动作白名单、功能模块检查、数值上下限和步长校验；请求经显示服务队列进入现有主循环，复用触屏动作与保存逻辑。投屏期间拒绝这些控制，需退出投屏再操作。提交成功表示队列已接收，使用刷新读取设备当前值；调节条位置与触屏原有行为一致，仅当前会话有效。

`GET /api/controls?group=display|vehicle|connection|media|system` 返回分组，单组响应小于 3072 字节；`POST /api/controls` 使用 `{ "action": "ratio", "value": 250 }`，传动比单位为百分之一。每项单独应用；不允许远程注入触屏校准采样。

新增 `GET /api/controller/candidates` 和 `POST /api/controller/scan`。蓝牙响应上限三端统一为 8192 字节，以容纳完整设备清单，请求上限保持 512 字节。

验证：`python3 tests/test_remote_controls.py` 编译真实分发代码并测试边界、功能禁用、队列失败与 JSON 大小；`node tests/dashboard_controls_check.cjs` 验证页面交互（需正式构建预览服务，可用 DASHBOARD_URL 指定）；Android 单元测试覆盖较大响应分片和超限拒绝。测试中的设备是模拟桥，不代表实车验收。

## 测试与正式构建

`npm --prefix vercel run preview:fnconnect` 在 8787 提供测试构建，输出到 `vercel/dist-preview/`。功能页无须连接即可展示全部远程控件、两种保护板配置及 GPS 辅助数据入口，所有这些控件的操作仅模拟，不向设备发送。页面会明确标注测试预览。测试清单在 `vercel/src/preview-controls.json`，与固件白名单一起维护。

`npm --prefix vercel run build` 输出正式资源到 `vercel/dist/`，供 APK 和正式部署使用；无连接时不展示控制项目，连接后点击「读取 / 刷新」，按设备返回的清单和保护板类型显示。测试与正式资源版本、输出目录相互独立。语言仍在设备设置中切换。

`node tests/dashboard_controls_preview_check.cjs` 对照固件白名单核对测试清单，检查 8787 全功能展示、模拟操作不发请求、窄屏布局，以及 8788 正式构建的能力读取限制。

## 爱车首页与 GPS 地图

首页「保护板」「控制器」进入各自的状态和配置入口；手机与 ESP32 的热点、蓝牙连接仍在设置页。长按卡片或空白处约 550 毫秒进入首页编辑：拖动卡片松手排序，右下角拖动缩放，可删除或从卡片库新增，点「完成」保存在本机 `bms.dashboard.home-layout.v1`，点「取消」还原。卡片库包含实时指标、远程控制清单中的每个动作、设备设置清单中的每个项目、GPS、历史及连接／更新等入口。正式模式按读取到的能力生成卡片，暂时不可用的已保存卡片保留位置记录，能力重新可用时恢复。

最近骑行优先读取最新会话的 `/api/history/samples`，HTTP／BLE 均使用每页 8 条的协议，依据 `flags & 1` 判断 GPS 有效性，无效定位会断开折线，`lon_e7/lat_e7` 除以 `1e7` 后绘图。一次读取最多 32 页，未读完明确显示「继续读取轨迹」；无历史会话时 HTTP 使用 `/api/gps/track`。轨迹数据来自 ESP32，不使用手机定位或虚构轨迹。GPS 地图需要设备连接，以及访问天地图底图的互联网连接。

本地 `.env.local` 的 `VITE_TIANDITU_BROWSER_TK` 取自 YunPu 的 `TIANDITU_BROWSER_TK`，该文件已忽略，不提交密钥；正式部署需配置同名浏览器环境变量。只使用浏览器 key，不复制服务器 key。SDK 地图放在独立 iframe 中，卡片移除时连同事件监听和地图文档一起清理。

回归：`node tests/dashboard_home_unit.cjs`、`node tests/dashboard_home_check.cjs`、`node tests/dashboard_gps_check.cjs`。GPS 自动化使用明确的设备和地图 SDK 模拟，覆盖坐标、定位断点、分页、延迟加载和卸载；不能代替真机轨迹验收。
