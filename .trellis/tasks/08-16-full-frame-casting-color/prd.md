# 投屏整帧显示与颜色修复

## Goal

让 Android 投屏画面像车机投屏一样以完整画面切换，不再让用户看到方块逐块刷新；同时确保 RGB565 颜色准确、持续投屏不花屏。

## Background

- 用户真机复测当前 `64x64` 分块方案后确认：速度比原先快一点，但仍能看到局部刷新，未达到整屏直接变化的体验。
- 用户真机确认白色正常，其余颜色错误，部分画面花屏。
- 旧任务 `07-12-android-low-latency-casting` 为控制设备端内存占用，明确排除了完整帧缓存；这会让分块写屏过程直接可见。
- 当前目标设备逻辑横屏分辨率为 `480x320`，一帧 RGB565 原始数据为 `307200 B`。
- 真机日志 `logs/serial-2026-08-16_00-16-54-cast-fix.log` 显示投屏会话期间约有 `8.34 MB` 空闲 PSRAM、最大连续块约 `8.25 MB`，足以容纳压缩输入和一个完整 RGB565 解码帧。
- 目标 ST7796U 使用 16 位 I80、`25 MHz` 像素时钟；纯像素数据的全屏传输理论时间约 `6.2 ms`，因此主要可见卡顿来自逐块接收即逐块提交，而不是 LCD 扫完整帧本身。
- 当前链路把 Android 生成的大端 RGB565 先按 LVGL 色彩格式转换，再由 I80 自定义绘制回调交换后发送；白色在字节序和红蓝通道互换下都保持不变，现象与链路色序契约错误一致，需用纯色矩阵在真机闭环确认唯一转换点。
- 仓库已通过 `esp_lvgl_adapter` 带入 `esp_new_jpeg`，无需新增第三方依赖；其 ESP32-S3 官方基准在 `480x320`、4:2:0、质量 60、RGB565_LE 输出下约为 `36 fps`。

## Requirements

1. 设备只显示已经完整接收并验证的帧，不向用户暴露同一帧的分块传输过程。
2. 使用质量 80 的 JPEG 完整帧作为默认投屏格式，目标发送帧率为 20 fps；极端画面超过设备声明的帧大小上限时允许降低 JPEG 质量，不允许无限增大消息。
3. 投屏协议必须具备清晰的单帧边界；截断、超限、方向错误、尺寸错误或解码失败的帧不得替换当前显示画面。
4. 修正 Android 图像读取、JPEG 色彩编码、固件 RGB565_BE 解码和 LCD 提交之间的颜色格式与字节序定义。
5. 投屏期间继续保持独占显示，普通 LVGL 刷新不得覆盖投屏画面；退出后仍按原流程恢复 UI 与业务服务。
6. 复用 Android 原生 Bitmap/JPEG、现有 `esp_new_jpeg`、PSRAM、显示适配器和 WebSocket，不新增第三方依赖。
7. 发送端只保留最新待发送画面；设备来不及处理时丢弃过时中间帧，不累积延迟。
8. 固件日志必须提供帧大小、解码时间、提交时间和有效帧率，便于真机复测继续定位瓶颈。

## Acceptance Criteria

- [ ] `480x320` 画面更新时，屏幕从上一完整帧直接切换到下一完整帧，肉眼不可见分块扫描过程。
- [ ] 连续动态画面以 20 fps 为目标；10 秒真机测试平均有效帧率不低于 18 fps，发送端不存在持续增长的待发送队列或延迟。
- [ ] 红、绿、蓝、黑、白、青、品红、黄纯色测试帧与 Android 源画面视觉一致，不发生固定红蓝互换或 RGB565 字节序错乱。
- [ ] 彩条、渐变和高细节测试图连续投屏不出现固定通道互换、随机彩点或撕裂。
- [ ] 截断、超限、错误尺寸 JPEG 和断线不会把半帧内容呈现在屏幕上；重新连接后的下一完整帧可恢复显示。
- [ ] 真机持续投屏无 panic、watchdog 或内存分配失败，退出投屏后常规 UI 正常恢复。
- [ ] 固件、Android debug APK 及相关最小回归测试通过。

## 实机验收记录

- `2026-08-16`：用户在当前目标板 `ESP32-S3 + ST7796U 16-bit I80` 上确认，整帧 JPEG 投屏速度和颜色均正常。
- 当前 RFC2217 桥接复核到的也是该 S3（`8 MB` PSRAM，MAC `ac:a7:04:f3:9b:68`）；它不能证明旧 ESP32 的 SPI 屏幕色彩结果。
- 严格的 10 秒 FPS、八色/渐变/高细节，以及旧 ESP32 和其他 I80 profile 的实测仍保持待完成，不能用本次 S3 验收替代。

## Out Of Scope

- Miracast、Android Auto、Google Cast、H.264/RTSP 等标准车机/视频协议。
- 无损 RGB565 差分模式、JPEG 与 RGB565 自动混合编码、自适应码率控制。
- 音频投送、触控回传、DRM 内容、iOS 客户端。
- 为本次目标新增第三方编解码或网络传输依赖。
