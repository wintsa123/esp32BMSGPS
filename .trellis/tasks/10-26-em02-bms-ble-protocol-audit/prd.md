# 鹿行 EM02 接入与 BLE 协议复核

## Goal

接入鹿行陆行管家 EM02 保护板，并确保蓝宝电量模块只可从 Web 配置。逐项对比现有保护板与控制器 BLE 协议，修复有可靠帧级证据的错误，避免把主机自测误当成真机兼容结论。

## Background

- 用户已明确要求添加鹿行 EM02，保留蓝宝，但只允许 Web 端选择；设备 LVGL 端在未激活时应将蓝宝置灰。
- 蓝宝轮询需要六位配对码。现有 Web 表单和 `/api/config` 没有该码的写入入口，单靠 Web 选择无法完成蓝宝轮询配置；当前 GET `/api/config` 还会明文返回此码。
- 控制器 BLE 层每次最多复制 128 字节通知；甲胄解析器允许 192 字节载荷（196 字节整帧），传输层与协议上限不一致。
- 现有协议基线及交叉验证报告记录了多个未决字段差异；Motexa 反编译参考与 host selftest 均不能代替真实设备抓包。

## Requirements

1. 增加鹿行 EM02 的保护板类型和只读 BLE 协议接入。按 Motexa 参考实现服务 `FFE0`、通知 `FFE1`、写入 `FFE2`，使用 Modbus 03 只读轮询，先读取设备身份并确认 EM02 后再发布遥测；不得添加参数写入、绑定配置、校准或升级命令。
2. 不改变现有 BMS 类型枚举的持久化数值；EM02 使用新的追加值，并贯通 NVS/API、BLE 生命周期、Web 选择、设备端显示和测试。
3. 保留蓝宝并允许 Web 选择；Web 必须提供六位数字配对码的配置/保存入口并安全回显当前配置状态。蓝宝在设备 LVGL 型号列表中始终不可选；当前配置为蓝宝时仍显示当前状态，未激活时呈灰色。点击或伪造 action 均不得将设备配置切换为蓝宝。
4. 对照 Motexa 参考与现有代码，复核已接入的保护板和控制器协议的 BLE GATT UUID/属性、请求帧、响应长度、校验、重组和遥测字段映射。仅修复可由可靠证据确认的错误；未确认语义和需要真机验证的项明确记录。
5. 修复控制器 BLE 通知长度边界与协议最大帧长不一致的问题，确保有效长通知可传入协议解析器，并保持缓冲边界安全。
6. 更新协议基线/交叉验证文档，明确 host selftest、ESP-IDF 构建和真机验证各自能支持的结论。

## Acceptance Criteria

- [x] 新增 EM02 类型可由配置文本稳定往返，不改变已有枚举/NVS 含义；设备身份未确认前不发布 EM02 遥测。
- [x] EM02 仅发送 Modbus 03 只读请求；碎片/粘连响应可正确组帧并校验，异常长度、CRC 错误和非 EM02 身份不产生遥测。
- [x] Web 可设置和保存蓝宝六位码，非法输入被拒绝；配置响应不暴露配对码明文；蓝宝可完成配置后的轮询请求生成。
- [x] LVGL 蓝宝行灰显且不可点击；已由 Web 设置为蓝宝时能标出当前项；直接触发蓝宝 action 不会修改设备类型。
- [x] 控制器合法通知的最大协议长度不会被固定 128 字节缓冲截断；超界输入不越界且有可诊断处理。
- [x] 对所有现有协议完成可追溯的差异清单；帧级证据充分的错误有回归测试，证据不足项保留为显式待实机验证事项。
- [ ] 相关 host selftests、配置/API 测试和固件目标构建通过；真机验证结果单独记录，未执行时不得宣称通过。

本轮验证：`scripts/run-host-selftests.sh` 及 EM02 `-Wall -Wextra -Werror` 自测通过；Python 测试仍有既有契约失败且环境缺少 `serial` 模块。ESP-IDF 固件构建因必须先生成 profile 且磁盘空间不足未完成，RFC2217 刷机未进入写入阶段；实体 EM02/控制器抓包未执行。

## Out of Scope

- EM02 写寄存器、绑定/解绑、校准、固件升级及任何修改保护板参数的功能。
- 将需要实车环境的 BLE 行为标记为已验证；除非本任务执行并记录相应真机抓包。
- 与上述配置、协议兼容无关的 UI 重排或控制器数据展示扩展。

## Decisions

- 追加 EM02 枚举值以维持现有 NVS 兼容性。
- 蓝宝 LVGL 端采用真正不可交互的灰显行，同时保留“当前配置项”标记能力；Web 配置仍有效。
- 协议纠错以 Motexa 参考/标准帧级证据为准；不确定差异不猜测修正。

## Open Questions

- 无阻塞需求问题。EM02 真机设备是否可用于本轮验收属于环境条件；若不可用，将协议硬件验证列为明确风险，不影响主机侧实现和测试。
