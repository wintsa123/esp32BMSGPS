# Android 低延迟镜像投屏

## 目标与用户价值

Android 手机连接设备 Setup AP 后，以低延迟镜像画面到 ESP32-S3 仪表。投屏是一个独占会话：进入后释放常规 LVGL UI 和可恢复业务资源，手机主动退出、连接断开或心跳超时后才恢复轮播仪表与业务服务。

## 已确认事实与约束

- 当前投屏目标配置为 `cast-s3-build`：ESP32-S3、16 位 I80 ST7796U、GT1151、PSRAM，物理分辨率为 `320x480`，默认逻辑横屏为 `480x320`。
- 现有 `/api/cast/info` 错误地固定上报 `320x240` 或 `240x320`，造成目标面板不能全屏。
- 现有 WebSocket RGB565 块通过可复用接收缓冲直接提交给异步面板 DMA；缓冲可能在传输完成前被下一包覆盖，且普通 LVGL 刷新没有被完全隔离，均会造成偶发花屏。
- ESP-IDF HTTP 服务、Setup AP、LVGL 9.5、`esp_lvgl_adapter` 和 Android Kotlin 客户端已存在。适配器已有 dummy-draw 模式，可接管显示并等待 DMA 完成。
- Setup AP 的 SSID/8 位数字密码策略、现有凭据二维码和默认中文 UI 约束不变。
- 用户已确认：投屏期间只保留显示、Setup AP、HTTP/WebSocket、主循环、看门狗和投屏链路所必需的资源；常规 LVGL 页面及可恢复业务服务应关闭或暂停。

## 范围内需求

1. 投屏协议升级为 v2；设备仅允许一个客户端，继续拒绝越界、过大或版本不匹配的数据包。
2. WebSocket 连接建立后，显示服务先进入投屏独占模式，再接受像素块；普通 LVGL 定时渲染、轮播、页面动画和输入动作不得覆盖投屏画面。
3. 投屏独占模式释放普通 LVGL 根页面、页面内容、静态仪表缓存和定时器；当前 profile 的控制器 BLE 与 GPS 停止或暂停。退出后重建 UI、恢复用户原有显示方向，并重新启动已暂停模块。
4. 固件保持无完整帧缓存。每个块最大 `64x64 RGB565`，在显示桥中转换为当前适配器所需字节序，并通过 dummy-draw 同步提交，直到 DMA 完成后才复用缓冲。
5. `cast-info` 返回真实的物理/逻辑分辨率和可选旋转；手机根据当前手机方向选择对应设备逻辑方向，先在手机端旋转和拉伸到完整面板，再发送转换后的 RGB565 块。
6. 手机竖屏时设备使用临时竖屏逻辑分辨率，手机横屏时使用临时横屏逻辑分辨率；方向变更时在完整帧边界切换，不保留黑边。投屏结束后恢复用户保存的设备方向。
7. 只有 App 主动停止、WebSocket 断开、心跳超时或协议失败导致的连接终止才能结束投屏；结束后恢复轮播和常规服务。协议失败按连接失败处理，不能保留不受控的显示会话。
8. MVP 是只读镜像：现有投屏发现页和 Setup AP 凭据二维码保持兼容，协议只传输画面、心跳与 ACK；设备不向手机发送触控或其他控制消息。

## 不在范围内

- Miracast、Google Cast、Wi-Fi Direct、H.264/RTSP、全帧缓存或设备端缩放。
- iOS 客户端、Google Play 发布、任何设备到手机的反向控制（含单指触控）、文字输入、DRM/安全内容和无障碍自动化。
- 停止显示驱动、Setup AP、HTTP/WebSocket、主循环或看门狗；这些是投屏链路本身的必要条件。

## 验收标准

- [ ] `cast-info` 对 `320x480` 目标正确报告两种逻辑方向及其真实尺寸；不再出现硬编码 `320x240`。
- [ ] 手机在竖屏、横屏以及会话内旋转后，设备画面均匹配手机方向并拉伸铺满整个逻辑面板；退出时恢复原设备方向。
- [ ] 红、绿、蓝、黑、白测试块颜色正确；持续传输不出现错色、撕裂或由接收缓冲复用导致的花屏。
- [ ] 投屏期间不执行普通 LVGL 刷新/轮播，常规页面与静态仪表缓存被释放，GPS 与控制器 BLE 不继续工作；显示、AP、HTTP/WebSocket、主循环和看门狗保持正常。
- [ ] App 主动停止、客户端断线、心跳超时和协议失败后，设备均在一次恢复流程中重建轮播 UI、恢复方向并重启暂停模块；不会卡在黑屏、投屏页或残留方向。
- [ ] 固件和 Android debug APK 均可构建；Android 单测覆盖方向选择、拉伸像素映射、块编码与 ACK 基线，固件自测覆盖协议边界与会话状态。
- [ ] 真机完成热点连接、竖横屏切换、主动退出、断线恢复、颜色测试及 heap 日志检查，无 watchdog、panic 或完整帧分配。
