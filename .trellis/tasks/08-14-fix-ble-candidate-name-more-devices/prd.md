# 修复蓝牙候选名称与更多设备点击映射

## Goal

让 BMS 和控制器蓝牙列表忠实显示每个 MAC 自己的广播名称，并让每个候选可被可靠
区分和点击；只有真实广播 `midea` 的设备才显示该名称，点击 `More devices` 只进入更多设备页。

## Background

- 用户确认现场只有两台真实 `midea`，但界面把其他蓝牙也显示成了该名称。
- 先前有限的真机调试日志只证明至少三条广告被解析为 `midea`，不足以证明整批候选名称正确。
- 真机同时发现无广播名称的候选。
- 当前列表渲染跳过无名候选，但点击仍按原候选数组行号计算，导致可见行与候选索引错位。
- NimBLE 的广告字段长度合同确认当前 `field->length - 1` 用法正确；现有名称缓存按完整 MAC
  精确匹配，快照层按候选数组复制，仍需通过混合名称数据和真机原始广告定位实际串名层。
- 蓝牙仅在用户进入 BMS/控制器列表后启动；本任务不得改变默认不可发现行为。

## Requirements

- BMS 和控制器列表使用同一套候选展示与点击映射。
- 每个 MAC 的名称只能来自该 MAC 的当前广告或该 MAC 自身的名称缓存，禁止沿用其他 MAC 的名称。
- 只有原始广告/该 MAC 缓存中名称为 `midea` 的候选才能显示 `midea`。
- 每个候选必须恰好占一条可见行，不得因缺少广播名称而跳过。
- 有名称候选显示名称和 MAC 后两段；无名称候选显示 `设备` 和 MAC 后两段。
- 保留候选 RSSI 显示；同名但不同 MAC 的候选必须可区分。
- 首屏候选超过 6 个时显示前 5 个和 `More devices`；点击该行仅进入更多页。
- 更多页点击候选时，连接确认框必须对应被点击候选的名称和 MAC。
- 保留默认蓝牙不可发现、按需扫描和现有分页返回行为。
- 不回退或混入工作区内与本任务无关的既有修改。

## Acceptance Criteria

- [ ] 两个不同 MAC、名称均为 `midea` 的候选显示不同的 MAC 后缀。
- [ ] 混合输入 `midea`、其他名称和无名称时，各 MAC 在扫描存储、快照与 UI 三层保持各自名称，不发生串写。
- [ ] 真机原始广告日志与最终列表逐 MAC 对照一致；现场只有真实两台 `midea` 显示该名称。
- [ ] 无名候选显示为 `设备 XX:XX`，且其前后行点击仍映射到正确 MAC。
- [ ] 含无名候选且总数超过 6 个时，点击可见 `More devices` 行进入更多页，不弹连接确认框。
- [ ] 更多页点击候选后，确认框中的候选与所点行一致。
- [ ] BMS 与控制器两条列表路径均通过模拟器回归检查。
- [ ] ESP32-S3 `esp32s3-n16r8-st7796u-gt1151` 构建成功。
- [ ] 通过固定 RFC2217 地址烧录成功，冷启动无 panic/watchdog，默认蓝牙不可发现。
- [ ] 真机复核同名候选可区分且 `More devices` 点击行为正确。

## Out Of Scope

- 根据名称猜测设备品牌或协议。
- 合并、过滤或重命名真实广播名称为 `midea` 的设备。
- 用 MAC 后缀掩盖错误名称而不修复首次串写的位置。
- 重构为每行独立 LVGL 控件或改变扫描、配对协议。
