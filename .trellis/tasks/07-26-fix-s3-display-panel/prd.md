# 修复 ESP32-S3 显示镜像与颜色

## Goal

让 ESP32-S3 板型的屏幕以正确的纵向方向和颜色显示，同时保持当前正确的触摸坐标。

## Confirmed Facts

- 用户报告 ESP32-S3 固件的画面上下镜像，颜色与 ESP32 固件相反。
- 实机确认 GT1151 触摸方向和坐标已经正确。
- S3 板型 `esp32s3-n16r8-st7796u-gt1151` 选择 ST7796 I80 面板和 GT1151 触摸。
- `esp_bms_lvgl_bridge` 的显示 HAL 统一设置面板旋转、镜像、LVGL 分辨率和触摸坐标变换，因此是首要排查边界。
- ST7796U 目录配置的物理坐标是 `320x480`；以 `LANDSCAPE` 启动时，HAL 会交换为逻辑 `480x320`，与实际 3.5 英寸横屏面板一致。
- 原厂 `11_touch` 例程确认此板在 I80 RGB565 模式使用 `BGR`、不交换颜色字节并开启面板反相；横屏方向的面板标志为 `swap_xy=1`、`mirror_x=0`、`mirror_y=0`。
- ESP LCD Touch 的软件变换先镜像、后交换 XY。用户实测横屏触摸上下反向，因此 GT1151 需要 `SWAP_XY=1`、`MIRROR_X=1`、`MIRROR_Y=0`，使显示 Y 坐标为 `320 - raw_x`。
- `main/idf_main.c` 会在显示 HAL 初始化前从 NVS 加载显示方向；默认版本升级会只覆盖旧版本默认值，后续用户选择的方向仍保留。

## Requirements

- R1：针对受影响的 ESP32-S3 板型，使用原厂参考的面板方向和颜色参数，并使 GT1151 坐标与最终横屏画面一致。
- R2：显示逻辑分辨率必须保持为现有面板原生横屏 `480x320`。
- R3：修正显示后，GT1151 触摸坐标和现有方向必须保持不变。
- R4：不得改变旧 ESP32 板型已有的显示行为。

## Acceptance Criteria

- [ ] S3 实机启动画面不再上下镜像，且触摸方向与修复前相同。
- [ ] S3 实机标准红、绿、蓝界面元素的颜色与旧 ESP32 固件一致。
- [ ] 受影响板型可完成固件构建；旧 ESP32 显示配置不被改动。

## Out Of Scope

静态 UI 的 `320x240` 布局和全屏适配在后续独立任务处理。本任务不改动触摸方向、UI 布局、旧 ESP32 固件或不相关板型。
