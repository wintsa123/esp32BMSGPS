# 蓝牙连接时支持 APK 查看修改并限制投屏

## 目标

手机仅通过设备蓝牙连接时，APK 仍可查看设备状态、能力和设置并提交允许的修改；投屏继续要求手机连接设备 Wi-Fi，蓝牙连接时不可启动投屏，并显示“请先连接设备 Wi-Fi”的中文提示。

## 范围

- 固件提供面向 APK 的受限 BLE GATT 请求/响应通道，覆盖现有设备状态、配置、能力清单及配置写入语义。
- Android APK 增加设备 BLE 发现、连接、读写和连接状态展示；现有 Wi-Fi HTTP 作为 Wi-Fi 模式传输，不改变端点契约。
- APK 在 BLE 模式显示/编辑设备页；记录、地图、OTA 等仅有 Wi-Fi HTTP 依赖的功能按能力/传输状态禁用并说明需要 Wi-Fi。
- 投屏入口只接受已绑定的 Wi-Fi 网络；蓝牙在线但 Wi-Fi 不在线时不可申请投屏权限，提示先打开并连接设备 Wi-Fi。

## 非目标

- 不通过 BLE 传输投屏画面。
- 不替换现有 BMS/控制器外设 BLE 协议。
- 不引入第三方 Android BLE 或网络库。

## 验收标准

- [ ] APK 能扫描并连接设备 BLE 广播，显示设备在线状态。
- [ ] BLE 在线、Wi-Fi 未连接时，仪表/设备设置可读取；允许的设置可保存并在重新读取后显示新值。
- [ ] BLE 在线时投屏按钮禁用，点击或状态说明明确提示“投屏需要先连接设备 Wi-Fi”。
- [ ] Wi-Fi 在线时投屏行为保持现有流程；BLE 断开不会导致 Wi-Fi 投屏状态误判。
- [ ] BLE 断开、超时、协议错误会清理旧设备数据并给出可重试状态。
- [ ] 固件与 Android 单测/构建通过，协议边界有最小自检。
