# BMS 骑行峰值记录

## Goal

每次设备开机视为一段旅程。为该旅程保存一条紧凑的 BMS 峰值摘要，供热点网页和 Vercel 控制页查询；最多保留最近 5 条。

## Background

- 已解码的 BMS 遥测提供包电压、带符号电流、SOC、单体压差和最多 6 个带有效性标志的温度。
- `esp_bms_idf_runtime` 已管理 BMS 状态、NVS 和本地 HTTP API；嵌入式网页与 Vercel 页面都直接调用设备 API。
- 默认 ESP32-WROOM-32E 只有 4 MB Flash、无 PSRAM；部分 S3 有 PSRAM。仓库没有 SD 卡驱动或通用文件系统。

## Requirements

- 一次设备开机至关机至多创建一条旅程记录。BMS 断开、停车、待机、速度状态和 GPS 状态均不得在本次开机内切分记录。
- 本次开机的首个完整有效 BMS 帧创建记录；无有效 BMS 数据时不创建空记录。下一次开机的首个有效帧才可创建下一条。
- 每条记录必须保存两组独立峰值快照：
  - 最大绝对电流发生时的包电压、原始带符号电流、单体压差、所有有效温度和 SOC。
  - 最大单体压差发生时的包电压、原始带符号电流、单体压差、所有有效温度和 SOC。
- 最大电流按原始带符号电流的绝对值严格比较，响应保留原始符号。最大压差按数值严格比较。相等或更小的采样不得改写记录。
- 只接受完整有效的 BMS 遥测；不得用断开、超时、部分帧或缺少核心字段的值创建或更新峰值。
- 首次创建及每次峰值突破都要持久化，以便突然断电后保留已达到的峰值；不得依赖正常关机回调。
- 历史按时间顺序最多保留 5 条；创建第 6 条时自动删除最早一条。
- 使用现有 NVS/Flash 作为唯一持久化来源。不得增加 SD 卡、文件系统、分区或 PSRAM 依赖；PSRAM 不作为历史记录的唯一来源。
- 新增只读 HTTP 接口，嵌入式热点网页和 Vercel 控制页显示空态及最近记录。默认中文，英文沿用设备设置中的既有语言切换。

## Acceptance Criteria

- [ ] 首个有效 BMS 帧创建一条记录；同一次开机内 BMS 重连或短暂超时不会新建记录。
- [ ] 最大绝对电流和最大压差分别只在严格突破时更新，且每个快照内字段均来自同一 BMS 帧。
- [ ] 连续 6 次有有效 BMS 数据的开机后，只能读取最新 5 条，顺序正确。
- [ ] 断电重启后，上一开机周期已持久化的峰值仍可读取；默认无 PSRAM 目标和有 PSRAM 的目标行为一致。
- [ ] 无效/部分 BMS 遥测不创建空记录、不覆盖已保存数据。
- [ ] `GET /api/bms/ride-records`、热点网页和 Vercel 页均能显示空历史和已保存记录，且不依赖云端中继。

## Out Of Scope

- 逐秒 BMS 曲线、全量轨迹、SD 卡/FATFS、云端同步、记录删除控件、TFT 首页改版、BMS 协议解析或分区调整。
