# 安卓蓝牙媒体控制

## 目标与用户价值

在设备轮播中新增一个音乐页，让已配对的 Android 手机通过 BLE 接收上一首、下一首、音量增减指令，并将当前媒体标题回传到 TFT。手机媒体音量是独立状态，绝不改变单片机的本地音量。

## 已确认事实与约束

- 固件当前使用 NimBLE，ESP32-S3/C3 构建不具备经典蓝牙 AVRCP；本功能必须通过现有 BLE 外设连接和 Android 配套 App 实现。
- 当前本机蓝牙配对、BMS 扫描和控制器扫描共用一个 NimBLE Host。蓝牙 Host 初始化的 GitNexus 影响分析为 CRITICAL：影响 6 条流程、3 个模块。
- 现有 `android-cast` 是 Android 10+ 的离线 Kotlin App；它目前只提供 Wi-Fi 投屏，适合增加 BLE 媒体桥接，不能以投屏 WebSocket 替代 BLE。
- 轮播页已有 BMS、仪表和可选投屏页；新页需要遵循相同的横向滚动、页面过渡和模拟器检查。
- `start.sh` 的模块目录是实际的编译期功能选择来源。新功能必须以 `phone-media` 模块控制，且要求 MCU 具备 BLE。
- 默认本地 Web UI 为中文；TFT 固有字体覆盖有限，音乐页固定文案使用现有中文/ASCII 字体，媒体标题按 UTF-8 原样传输并按 UI 可见宽度截断。
- 本任务不改变 Setup AP 的 SSID、密码或二维码策略。

## 范围内需求

1. 新增 `phone-media` 固件模块和 `ESP_BMS_FEATURE_PHONE_MEDIA` 编译开关。模块未选中时，不创建音乐页、不注册媒体 GATT 服务、不添加 BLE 广播服务 UUID。
2. 模块选中时，固件在既有已加密、已绑定的本机 BLE 连接上提供私有媒体服务：设备通知手机控制命令，手机写入媒体状态与当前标题。
3. 音乐页必须在横向轮播中显示连接/播放状态、当前媒体标题、上一首、下一首、手机音量减和手机音量加四个触控入口；断开或未授权时控件不可误导为可用。
4. 固件处理触控命令时只发送 BLE 命令，不修改 `runtime.volume_percent`、音频反馈音量或其 NVS 配置。
5. Android App 新增前台 BLE 媒体服务：扫描/连接设备、订阅设备命令、请求系统通知访问权限、从活动 `MediaSession` 获取标题，并执行上一首、下一首和 `STREAM_MUSIC` 音量调整。
6. Android App 在 Android 10+ 上声明并申请需要的蓝牙权限；Android 12+ 兼容运行时 `BLUETOOTH_SCAN`/`BLUETOOTH_CONNECT` 权限。用户未授予通知访问时必须清楚显示授权入口，不能声称媒体控制已可用。
7. 为协议边界和 UI 变更添加最小可运行检查；生成或更新的 UI 预览必须存放在根目录 `preview/`。

## 不在范围内

- iOS、经典蓝牙 AVRCP/A2DP、音乐音频流传输、封面图、播放列表或播放/暂停控制。
- 设备端持久化媒体标题、同步手机和设备音量、修改手机默认播放器或绕过 Android 通知访问授权。
- 为任意 CJK 媒体标题新增大字库；标题传输保留 UTF-8，实际字形受当前 TFT 字库覆盖限制。

## 验收标准

- [ ] 构建配置中可以选择 `phone-media`；未选择时，固件和模拟器均不包含音乐页/媒体 GATT UUID，选择时包含两者。
- [ ] 设备启用本机蓝牙并完成加密配对后，Android App 可连接并订阅命令；BLE 断开后音乐页显示断开状态并拒绝发送控制指令。
- [ ] 音乐页可显示 Android 当前活动媒体的标题，并在媒体切换或元数据变化后更新。
- [ ] 四个设备触控操作准确映射为 Android 上一首、下一首、媒体流音量减、媒体流音量加；设备本地 `volume_percent` 不因此改变。
- [ ] Android 未取得通知访问、没有活动媒体会话、BLE 权限拒绝、扫描失败和连接断开均有可理解的状态，不崩溃或无限重连。
- [ ] 相关 C/Kotlin 单测或自检、Android debug APK、启用和禁用该功能的固件构建、LVGL 模拟器截图与检查均通过；更新预览位于 `preview/`。
- [ ] 通过项目 RFC2217 桥刷写一次功能开启的固件，并确认启动、BMS/控制器 BLE 共存和手机媒体控制的真机路径没有 panic 或 watchdog。
