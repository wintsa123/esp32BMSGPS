# 显示控制器 P/R 档位

## Goal

让仪表显示的控制器方向状态与真实 FarDriver 实时帧一致：空挡显示 `N`、前进显示 `D`、倒车显示 `R`；不能从遥测确认的停车状态不伪造为 `P`。

## Confirmed Facts

- APK 原生库 `libfd_protocol.so+0x11c38` 将紧凑实时帧 `frame[4] & 0x03` 存为其公开的
  `gear`。本项目的 `data[2]` 对应该字节，却错误读取 bit 2-3 并将 `0` 改写为 `3`。
- APK 的 `fdGetTelemetry()` 将这个低两位值作为第 11 项导出，`FardriverTelemetry.gear` 是唯一
  档位遥测字段；`FardriverTelemetry` 没有停车或其它方向状态字段。
- APK 仪表映射为 `0 -> N`、`1 -> 前进`、`2 -> R`、其它值 -> `?`。前进在 APK 可由额外配置显示
  为速度模式 `1/2/3`，本项目尚未读取该配置，因此统一显示为方向 `D`。
- APK 的 `P Gear` 和 `Auto Return P` 只来自控制器配置；静态解析没有可用于确认当前 `P` 状态的
  实时位。
- 控制器页、普通速度仪表和火刃仪表均读取 `controller_gear`；普通速度和火刃在控制器离线或
  无有效档位时错误回退显示 `1`。控制器和火刃仪表使用只含数字的定制字体，需改用已有 ASCII 字体
  才能渲染 `N/D/R`。

## Requirements

- 从实时帧低两位保留原始档位值，并在所有现有档位显示处使用同一个状态格式化函数。
- 有效且在线时显示 `0 -> N`、`1 -> D`、`2 -> R`；值 `3`、离线和无效档位均显示 `-`。
- 控制器页、普通速度仪表和火刃仪表必须使用能渲染 ASCII 字母的已有字体。
- 在新的实时协议证据出现前，禁止将任何值显示为 `P`。
- 对原始值提取和统一显示格式添加最小 host 自检。

## Acceptance Criteria

- [ ] 真实帧字节低两位 `0`、`1`、`2` 分别使三个现有仪表显示 `N`、`D`、`R`；值 `3` 显示 `-`。
- [ ] 控制器离线或档位无效时，三个仪表显示 `-`，不再显示虚假的 `1`。
- [ ] 当前版本不显示 `P`，且任务文档记录这是 APK 未提供实时状态的结果。
- [ ] 协议解析自检、受影响的 UI 检查、`git diff --check` 和 GitNexus 变更检测通过。

## Out Of Scope

- 向控制器发送档位、倒车或停车控制命令。
- 在没有协议或实机证据时猜测 P/R/N/D 编码。
