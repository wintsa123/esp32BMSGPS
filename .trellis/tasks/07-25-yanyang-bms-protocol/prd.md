# 彦阳 BMS 协议适配与目录重组

## Goal

从随仓库提供的 `yy.apk` 提取并验证彦阳 BMS 的 BLE 协议，实现与现有保护板相同的连接、数据读取和字段转换能力；同时将已配置的保护板协议代码按品牌拆分到独立目录。

## Confirmed Facts

- `yy.apk` 位于仓库根目录，是 23 MB Android APK，可作为协议逆向输入。
- 父任务 `07-21-bms-ble-protocol-suite` 已规定协议 parser 必须与 NimBLE 解耦，并覆盖分包、粘包、损坏帧、校验和字段边界。
- 项目现有 BMS BLE 组件位于 `components/esp_bms_bms_ble/`，设备设置和本地 Web UI 均已有保护板相关入口。
- 用户要求在保护板设置中增加“彦阳 BMS”选项，并要求协议字段按原协议代码的转换规则实现。
- 用户要求把当前已经配置的保护板协议代码按各自品牌目录归类。
- APK 未混淆的 `com.yybms.app.util.BMSDataClass` 和 `BleDataUtils` 是协议证据来源；`PROTOCOL_YY = 0` 为默认协议。
- 彦阳 GATT 服务为 `0000FE59-0000-1000-8000-00805F9B34FB`，读写特征为
  `8EC90001-F315-4F60-9FB8-838830DAEA50` 与
  `8EC90002-F315-4F60-9FB8-838830DAEA50`，订阅使用标准 CCCD。
- APK 的只读轮询依次读取 `0x003F/4`、`0x0001/47`、`0x0030/42`、
  `0x005A/22`。请求和响应为 Modbus RTU 形状，CRC 初始值为 `0xFFFF`，
  CRC 在线上按高字节、低字节排列。
- 主遥测页 `0x0001` 使用大端字段：电芯数偏移 15、温度数偏移 16、包压
  偏移 25（`/1000 V`）、电流偏移 29（有符号 `/100 A`）、最高/最低单体
  偏移 37/39（mV）、SOC 偏移 41（`*0.4%`）、实际/额定容量偏移 43/45
  （`/10 Ah`）、单体电压从偏移 47 开始（mV）。温度为原始无符号字节减
  40 摄氏度：`T1=83`、`MOS=84`、`BAL=85`、`T2=86`；仅投影这四路，
  不以未证实字节填充 `T3/T4`。
- 当前 BLE 组件实际只含 ANT 解析；JK/JBD/Daly 仅有选择项，不能创建空目录或
  伪称已实现。此次将现有实现迁至 `protocols/ant/`，新增
  `protocols/yanyang/`。

## Requirements

- 从 APK 的代码和资源中识别彦阳 BLE 的扫描特征、服务/特征 UUID、连接或认证步骤、请求/通知帧、长度与校验规则，以及所有展示字段的缩放、符号和字节序转换。
- 以独立、可测试的 C 协议实现接入既有 BMS BLE 状态机；不得猜测未被 APK 代码或实机数据证明的协议常量或字段。
- 在 TFT 和本地 Web 的保护板类型选择中新增“彦阳 BMS”；遵守项目语言约束，TFT 无中文字库时使用 ASCII 标识。
- 将现有已配置的保护板协议实现按品牌目录组织，保持现有选择项、持久化配置和已支持协议的行为兼容。
- 为彦阳解析器保留黄金帧和字段边界检查，覆盖校验失败、分包和粘包。

## Acceptance Criteria

- [ ] APK 中可复核地定位协议实现，并记录服务/特征、收发序列、帧格式、校验及字段换算依据。
- [ ] 设备可选择彦阳 BMS，并通过既有 BLE 生命周期完成发现、连接、收发和状态更新。
- [ ] 所有从彦阳帧到内部数据模型的数值均按 APK 代码的字节序、比例、偏置和符号规则换算。
- [ ] 已有保护板协议按品牌目录归类，构建配置和既有选择项保持兼容。
- [ ] 至少一组可复现协议测试验证正确帧和异常流输入。

## Out Of Scope

- 未经 APK 证据或用户提供实机抓包支持的写配置、升级或其他控制命令。
- 与 BMS 无关的 BLE、UART、RS485、CAN 或界面重设计。

## Open Questions

  校准、升级或其他控制命令。
