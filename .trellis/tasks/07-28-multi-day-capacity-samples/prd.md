# 多日容量估算样本

## Goal

基于同一 BMS 的多次骑行和充电数据，长期估算电池实际容量；仅接受质量合格的样本，且以固定、受控的 NVS 空间保存有限历史。

## Confirmed Facts

- 现有估算仅保存单个估算值、已接受循环电量和样本计数；样本计数上限为 4，不能复核或剔除已持久化的历史样本。
- 现有有效样本要求 SOC 单向变化至少 20%，循环电量至少 1000 mAh；连接重建和积分间隔超过 3 秒会重置锚点。
- JK/ANT 使用 BMS 上报的累计循环电量；Daly/彦阳以带实际时间戳的电流积分生成累计循环电量。
- 同仓库的骑行记录使用固定大小的循环缓冲区，最多保存 5 条记录；容量样本也必须采用固定上限，不能随天数无限增长。

## Requirements


- R1: 仅针对相同 BMS 类型和绑定 MAC 聚合跨骑行、跨充电、跨重启的容量样本。
- R2: 保存有限数量的原始有效样本，以便跨天计算平均值并在后续样本到达时识别离群值。
- R3: 拒绝不完整或不可信的采样段，包括 SOC 跨度不足、循环电量不足、断连或积分时间不连续、SOC 方向反转，以及相对历史明显偏离的候选值。
- R4: 样本历史固定保留 8 条；NVS 字节数必须固定、可在源码中审计，并在满额时采用确定性的淘汰策略。
- R5: 旧版仅含单一估算值的 NVS 数据必须安全忽略或迁移，不能造成异常容量显示。
- R6: 仅在至少积累 3 条合格样本后，才将估算容量标记为可显示。
- R7: 当已有至少 3 条历史样本时，候选容量偏离历史中位数超过 25% 必须被剔除。

## Acceptance Criteria

- [ ] 同一 BMS 的多个合格骑行或充电段可跨重启、跨多天参与容量估算。
- [ ] 发生任一不合格条件时，候选样本不会进入持久化历史，也不会改变最终估算。
- [ ] 样本历史有明确的固定条目上限和最大字节数；连续多日使用不会增加 NVS 占用。
- [ ] 少于 3 条合格样本时，界面仍显示正在估算，不显示不稳定的容量数值。
- [ ] 历史满额后，新合格样本按定义的策略替换最旧样本，最终估算仍可正常更新。
- [ ] 有至少 3 条历史样本时，偏离历史中位数超过 25% 的候选值不会写入历史或改变最终平均值。
- [ ] BMS 类型或 MAC 改变时，旧 BMS 的历史不会参与新 BMS 的估算。
- [ ] 新增或修改的估算逻辑有可执行的自检，覆盖合格、多日持久化、历史满额和离群样本。

## Notes

- 样本大小和数量是本任务的首要约束；8 条仅含容量值的原始样本与元数据组成的固定 NVS blob 不超过 80 字节，不保存逐点遥测、日期或无上限日志。
