# Design

## Scope

将现有单值平滑估算替换为同一 BMS 的固定 8 条原始容量样本历史。现有遥测链路、20% SOC 跨度、1000 mAh 最小循环电量、方向一致性和积分中断保护均保留；不增加 BLE 轮询、RTC、日志或 UI 控件。

## Data Model

`esp_bms_capacity_estimate_t` 保存：

- 最多 8 条 `uint32_t` 容量样本。
- 当前条目数和下一个写入槽位。
- 由历史样本重新计算的算术平均值。
- 现有锚点、方向和循环电量状态。

NVS 记录升级到版本 2，固定布局保存 BMS 类型、MAC、8 条样本、条目数、写入槽位、最终平均值和最后接受的循环电量。它不保存日期或逐点遥测；多天支持来自 NVS 持久化。记录必须有编译期大小断言，大小不超过 80 字节。旧版本 1 没有原始样本，读取时安全忽略并从新样本重新建立估算。

## Candidate Acceptance

1. 继续仅由已有的合格遥测段产生候选容量：SOC 单向变化至少 20%、循环电量至少 1000 mAh，且没有连接重建、方向反转或超过 3 秒的电流积分中断。
2. 少于 3 条历史样本时，结构合格的候选值直接写入历史，用于建立基线。
3. 有至少 3 条历史样本时，以当前样本的中位数为基线。候选值与中位数的相对差严格大于 25% 时拒绝；使用 64 位中间值避免乘法溢出。
4. 无论接受还是拒绝，候选段结束后都重设锚点，避免异常 SOC 段持续污染后续计算。
5. 接受时写入下一个环形槽位；满 8 条后替换最旧条目。最终估算为全部保留样本的无权算术平均。

## Readiness And Persistence

至少 3 条样本才置 `ready`，所以现有 UI 会继续显示“估算中”直到数据足够。仅接受、清空或身份变化会标脏并沿用现有延迟重试持久化路径；被拒绝的离群值不触发 NVS 写入。

按 BMS 类型和绑定 MAC 隔离历史。类型或 MAC 改变时清空内存样本和显示值，旧 BMS 的数据不能参与新 BMS 估算。

## Compatibility And Rollback

版本 1 blob 会被忽略，不会被误解为版本 2 的样本数组。回退到旧固件时，旧固件同样会因版本不匹配忽略版本 2 数据并重新估算；不会读取错误容量。
