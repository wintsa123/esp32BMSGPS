# 防止设置滑动误入二级菜单

## Goal

让 ESP32-S3 的 GT1151 电容触摸屏在设置列表滑动时，不会在手指尚未松开前或松开后误进入某个二级菜单。

## Confirmed Facts

- 目标设备是 ESP32-S3，使用电容触摸屏。
- 问题发生在 TFT 设置页面的列表滑动操作中。
- 用户预期滑动保持为滚动手势；只有未发生实际滚动的轻触才进入二级菜单。
- 活跃 S3 板型为 ESP32-S3 N16R8、GT1151、LVGL 9.5.0；GT1151 使用 I2C 100 kHz（SCL 40、SDA 41）和低有效 IRQ GPIO 42。
- GT1151 的状态寄存器 `0x814E` 的 bit7 是数据缓冲区就绪位；bit7 为 `0` 时，坐标数据无效，不能被解释为松手。
- 当前 GT1151 驱动只使用状态寄存器的低四位触点数。无效状态 `0x00` 因而会传成 `count == 0`，LVGL 适配器随即报告 `LV_INDEV_STATE_RELEASED`，并在手指仍按住时派发设置条目的 `LV_EVENT_CLICKED`。
- 设置二级导航只在 `LV_EVENT_CLICKED` 执行；不存在 `PRESSED` 直接导航路径。前一版给设置卡片添加 `LV_OBJ_FLAG_SCROLL_CHAIN_VER` 后真机问题变得更糟，必须撤销。

## Requirements

- R1. GT1151 的无效状态报告不能把已接受的按住触点变成 LVGL 松手。
- R2. 有效的零触点报告必须仍能正常松手；不延迟或吞掉真实松手。
- R3. 不改变正常轻触进入二级菜单、设置列表滚动、返回滑动和其他独立手势。
- R4. 修复只作用于 GT1151 配置，复用现有触摸读取回调，不新增轮询、定时器或依赖。
- R5. 状态寄存器读取失败时回退现有驱动读取路径。

## Acceptance Criteria

- [ ] AC1. 手指按住并开始滑动设置列表时，不会在松手前进入二级页面。
- [ ] AC2. 滑动结束松手后，不触发本次拖动起点或终点菜单项的导航。
- [ ] AC3. 未超过滚动判定阈值的轻触仍可正常打开对应二级菜单。
- [ ] AC4. 有效零触点帧仍会释放，现有设置返回手势和普通菜单导航保持可用。
- [ ] AC5. 非 GT1151 板型、全局 LVGL 拖动阈值和设置布局保持不变。

## Out Of Scope

- 校准硬件、修改 GT1151 组件依赖或全局触摸阈值，或重做设置页面布局。
- 为非 GT1151 板型引入新的手势框架、轮询或通用点击延迟。

## Implementation Decision

- 在共享触摸读取回调中先读取 GT1151 的 `0x814E`。仅当 bit7 为 `0` 且本序列已有已接受触点时，返回缓存的完整触点并跳过 GT1151 驱动读取。
- bit7 为 `1` 时保持现有驱动路径，低四位为零则正常松手；状态读取失败也保持原路径。触摸过滤在每次接受触点时更新缓存，拒绝尖峰时恢复完整缓存点。
