# 实施计划

1. 读取控制器与火刃创建/更新函数，以及现有 320x480 模拟器截图。
2. 在修改 `create_controller_dashboard()`、火刃竖屏创建函数和创建路由前运行 GitNexus
   上游影响分析。
3. 增加精确 320x480 的手工几何分支，并按需求微调 240x320 竖屏；横屏分支不变，不使用
   缩放 API。
4. 扩充最小模拟器烟雾断言以覆盖新的原生竖屏对象存在性。
5. 构建模拟器，回归 320x480、240x320、480x320，生成并查看两张预览图。
6. 运行 Trellis 质量检查、GitNexus 变更检测、规格更新和任务限定提交；不混入现有用户改动。

## 风险与检查

- 最大风险是硬编码坐标在 320x480 下重叠；通过 headless 截图和人工目视检查消除。
- 速度、档位、温度和辅助指标标签必须继续由现有快照更新函数驱动。
- 使用 `rg` 验证新竖屏函数没有缩放 API 调用。
