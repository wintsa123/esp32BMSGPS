# GT1151Q 原生手势与校准策略

## Goal

让 `esp32s3-n16r8-st7796u-gt1151` 使用 GT1151Q 的原生手势寄存器处理有限的全局导航，
同时移除该电容触摸配置的人工屏幕校准体验。坐标触摸继续服务于需要精确位置的 LVGL 控件。

## Confirmed Facts

- 活跃 S3 profile 为 `esp32s3-n16r8-st7796u-gt1151`，输入为 GT1151 I2C；目录配置使用
  16 位 I2C 命令和 8 位参数，因而可直接访问 GT1151 寄存器。
- 桥接层已在 `touch_read_with_diagnostics()` 中读取 GT1151 状态寄存器 `0x814E`，以避免
  无效缓冲区状态被误判为松手；该修复必须保留。
- 工程尚未读取 `0x814C`，因此尚未处理 GT1151Q 的原生手势码。
- 当前每个有效坐标帧都会进入通用 NVS 校准映射，设置页也无条件提供“屏幕校准”；这对已
  自动校准且实机坐标方向已确认正确的 GT1151Q 不必要，但 XPT2046 等其他输入仍依赖该能力。
- 仪表主页面当前由 LVGL 坐标拖拽切换横向轮播；同一次手势不能同时由该路径和 GT1151Q
  原生手势路径提交导航，避免重复翻页。
- 现有 UI 已使用 `LV_EVENT_LONG_PRESSED` 实现快捷面板编辑等长按交互，因此可继续由坐标
  触摸提供长按；GT1151Q 原生码表无需补造长按值。
- 当前 UI 没有 LVGL group、keypad input 或焦点导航，板级配置也没有 `0xC1/0xC2/0xC4/0xC8`
  低四位键值的产品语义。四个键值不能可靠地直接对应数量不固定的设置行或下拉选项。
- 同版本 `espressif/esp_lcd_touch_gt1151` 驱动将 `0x814E` 作为坐标状态寄存器，读完坐标帧
  后向该地址写入零确认；驱动不读取或写入 `0x814C`。本任务不修改 `managed_components/`。
- 显示服务在持有 LVGL bridge 锁的单一任务内调用 `lv_timer_handler()`，因此可在同一任务内将
  bridge 已采集的手势转交给 UI，不需要额外 FreeRTOS 任务或跨线程 LVGL 调用。

## Requirements

- R1. 仅对 GT1151Q profile 禁用校准映射、隐藏校准入口并忽略相关校准动作；非 GT1151
  profile 的校准流程、NVS 数据和旋转兼容性保持不变。
- R2. 仅在 GT1151Q 输入路径读取 `0x814C`，识别用户确认的原生手势码；未知、保留和读取
  失败的值不得触发 UI 动作。
- R3. 原生手势只承担离散全局导航；按钮、列表、滑条、键盘和其他需要位置的交互继续使用
  坐标触摸。
- R3a. 首版须识别左滑、右滑、下滑、上滑、双击和 GT1151Q 按键单击码。左/右滑继续服务于
  仪表主轮播，下滑打开快捷菜单，上滑仅关闭已打开的快捷菜单。
- R3aa. 双击必须能被输入层识别和诊断验证，但当前没有已批准的业务功能；不得为它新增无消费者
  的 UI action、任意默认副作用或未来配置框架。
- R3b. GT1151Q 按键单击码须能驱动设置页选项和快捷菜单中的按钮：`0xC1` 为上一项、
  `0xC2` 为下一项、`0xC4` 为确认、`0xC8` 为返回/取消。不得把未知键值或普通坐标轻触
  误解释为按键激活。
- R3c. 用户提供的 `0x814C` 原生码表没有长按码；本任务不伪造硬件长按手势。若产品需要长按，
  复用现有 LVGL 的坐标长按能力。
- R3d. 若按键单击要覆盖设置页和快捷菜单，必须定义四个键值的导航语义及可见焦点状态；不得
  将键值硬编码为特定页面行号或像素坐标。
- R4. 原生手势与 LVGL 坐标拖拽在同一页面、同一次手势中必须互斥；实现前以实机日志确认
  `0x814C` 的可读时机和确认/清除语义。
- R5. 保留现有 GT1151 `0x814E` 缓冲区就绪位兼容修复，不新增依赖、额外轮询任务或通用手势
  框架。
- R6. 触控逻辑的变更须通过 S3 profile 构建及 RFC2217 实机日志验证；不得覆盖工作区已有
  未提交变更。

## Acceptance Criteria

- [ ] AC1. GT1151Q 的设置页不再显示或进入人工屏幕校准，且不会加载、应用或重写校准 NVS
  数据；非 GT1151 profile 的既有校准流程仍可用。
- [ ] AC2. 每个确认支持的 `0x814C` 手势只提交一次预期动作；未知值、I2C 读取失败和普通
  轻触均不产生误动作。
- [ ] AC3. 启用原生手势的页面不发生一次滑动触发两次页面导航；未启用的页面仍保留原有 LVGL
  坐标拖拽、列表滚动和控件点击。
- [ ] AC3a. 下滑仅打开快捷菜单、上滑仅关闭已打开的快捷菜单；双击被识别并记录但不产生业务
  副作用；确认支持的按键单击码可激活设置页选项和快捷菜单按钮。
- [ ] AC3b. 设置页和快捷菜单的当前按键焦点可见；上一项/下一项循环或在边界保持稳定，确认
  仅激活当前焦点，返回/取消优先关闭弹层或返回上一层。
- [ ] AC4. GT1151 `0x814E` 无效缓冲区状态不会造成按住期间的错误松手，真实松手仍可正常
  释放。
- [ ] AC5. S3 profile 构建、相关自测、GitNexus 变更检测和 RFC2217 实机验证均通过，无
  panic、WDT、重复导航或触摸回归。

## Out Of Scope

- 为其他触控控制器增加原生手势支持。
- 新增手势配置页面、可配置映射、复杂手势框架、伪造原生长按码或更改 GT1151 固件配置。
- 用原生手势取代全部坐标触摸交互。

## User Decision

- GT1151Q 按键单击低四位采用统一导航：`1` 为上一项、`2` 为下一项、`4` 为确认、`8` 为
  返回/取消。
- GT1151Q 上滑只关闭已打开的快捷菜单；下滑打开快捷菜单。
- GT1151Q 双击当前仅作识别与诊断验证，待具体业务功能提出后再绑定。

## Technical Verification

- 首次实机测试记录 `0x814C` 原始值、相邻 `0x814E` 状态和每次已派发语义手势。除非日志和
  数据手册共同证明需要，不向 `0x814C` 写确认值；现有 `0x814E` 坐标帧确认保持不变。
