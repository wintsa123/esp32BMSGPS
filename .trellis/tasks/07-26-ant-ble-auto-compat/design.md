# 设计：ANT BLE 自动协议识别

## 范围

`bms_type=ant` 代表 ANT 品牌而非单一线上协议。新版与旧版 BLE 共用同一 GATT 服务和特征，因而完成订阅后才可通过只读请求和经过校验的响应分类。JK、JBD、Daly、彦阳路径不变。

## 状态与数据流

1. 重置连接时把 ANT 协议状态清为 `unknown`，清空协议流缓冲与探测计时。
2. 订阅完成后向 `FFE1` 写入新版状态读取帧。
3. 收到通知时，依据前导字节分别喂给新版/旧版纯 C 流解析器；解析器仅在完整校验帧时返回遥测。
4. 第一份有效遥测锁定协议并更新仪表；无法解析、CRC 错误或半包不会改变锁定状态或遥测时间戳。
5. 新版探测超时后发送旧版 `DB DB 00 00 00 00` 读取帧；旧版被锁定后以同一只读请求按现有轮询间隔刷新。
6. 所有探测都失败则保持未识别状态并从下一次连接/超时轮次重新开始，不将设备误标为在线。

## 边界

- 旧协议解帧、校验、字段转换和旧请求构建在 `protocols/ant/` 的纯 C 模块中；其宿主自检不依赖 NimBLE。
- `esp_bms_bms_ble.c` 仅保存协议识别状态、管理计时和选择轮询请求，不复制解析规则。
- 为避免 UI 选择协议，运行时状态仅用于当前连接生命周期；不会写入 NVS 或 HTTP 配置。

## 安全与兼容性

- 两种探测帧都是上游已验证的只读状态命令；不借用旧协议的写/认证帧。
- 按完整帧前导字节和校验锁定，不能以同 UUID、名称或局部字节判断。
- 保持既有新版数据字段和请求字节不变，以免回归现有已实测设备。

## 验证材料

- 新版黄金帧：上游 `tests/components/ant_bms_ble/frames_16s_status.h`。
- 旧版黄金帧：上游 `tests/components/ant_bms_old_ble/frames_14s.h`。
- 通过本项目 `scripts/run-host-selftests.sh` 编译运行新增 ANT 自检，并使用 ESP-IDF 目标构建验证 BLE 状态机。
