# 设计：安卓 Wi-Fi 投屏交互与 UI 优化

## 边界

改动限定在现有 Android 投屏 App 及固件投屏接入边界。`MainActivity` 继续使用 Android 原生 View 构建一个操作页；`CastService` 继续拥有投屏生命周期和传输，不改变编码或帧协议。

不引入 Compose、第三方 UI 库、导航框架或为未来功能准备抽象。普通浅色主题沿用现有 `AppTheme`。

## 交互状态

Activity 维护最小的 UI 状态：等待扫码、连接热点、查询设备、就绪、申请投屏权限、启动/连接投屏、投屏中、停止和失败。状态统一驱动说明文案、设备摘要以及主操作按钮的文字、启用状态和动作，避免各回调直接零散修改控件。

当系统已有活动 Wi-Fi 时，Activity 绑定该 Wi-Fi 并直接查询 `192.168.4.1`。能力查询、Service Intent 和 WebSocket 握手均不携带热点密码。设备投屏二维码编码仅含固定主机和协议版本的 `fuckingbms://cast/v1` 深链，避免依赖互联网落地页或泄露 WPA2 凭据。

热点请求和能力查询各有一个在途标记。生命周期恢复只在没有在途操作且尚未就绪时继续；手动刷新复用同一路径。网络丢失会清空设备能力、停止服务并回到可重试状态。

`CastService` 的状态广播增加稳定的状态类型，显示文字仍由 Activity 生成。服务开始连接、传输成功、最终失败和销毁时上报状态，使停止按钮与真实运行状态一致。广播限定当前包。固件 WebSocket pre-handshake 只拒绝第二个客户端，不执行密码认证。

## 页面布局

使用 `ScrollView` 包含单列 `LinearLayout`，保留系统按钮样式和普通浅色主题。页面按标题、状态、设备信息、主要操作、辅助说明排列。只保留一个随状态切换的主要投屏按钮和一个连接/重试操作；删除无法执行的 Back/Home 占位按钮。

尺寸使用 dp/sp 转换和明确边距，不增加装饰性卡片、图片或动画。预览只覆盖手机 App 操作页，保存到 `preview/`。

## 兼容与回滚

保持 minSdk 29、Setup AP WPA2、标准 Wi-Fi 二维码、协议版本检查和 MediaProjection 授权流程。回滚涉及 Android 投屏文件、固件投屏接入边界和新增预览，不要求数据迁移。
