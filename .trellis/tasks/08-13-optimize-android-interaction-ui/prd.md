# 优化安卓端交互逻辑与 UI

## 目标与用户价值

优化现有 `android-cast` 手机 App 的操作流程、状态反馈和界面层级，使用户能清楚判断热点连接、设备就绪和投屏状态，并用更少步骤完成投屏操作。

## 已确认事实与约束

- Android 客户端位于 `android-cast`，是 Android 10+ 的离线原生 Kotlin 应用。
- 应用当前不依赖 Compose、XML 页面布局或第三方 UI 库；应优先复用 Android 原生组件和现有代码，避免为视觉优化引入新框架。
- `07-12-android-low-latency-casting` 已负责投屏协议、连接和受限反控；`07-29-android-bluetooth-media-controls` 已规划 BLE 媒体控制。本任务不重复新增这些能力。
- 当前工作区的 `MainActivity.kt` 与 `CastService.kt` 已有未提交修改，后续实现必须保留并兼容。
- 默认用户界面语言为中文；若提供英文切换，入口必须位于设备设置中。
- 新增或更新的 UI 预览图必须放在仓库根目录 `preview/`。
- 本轮使用现有普通浅色主题，不增加深色主题、主题切换或自定义配色系统；投屏后的手机画面不属于 App 操作页 UI。
- 当前界面全部在 `MainActivity.content()` 中以原生 `LinearLayout`、`TextView` 和 `Button` 构建，没有页面导航结构。
- `connectExistingWifiOrLoadInfo()` 同时由 `onCreate`、`onResume` 和“连接/刷新设备”按钮调用；GitNexus 将其映射到 6 条 Activity 流程。实现阶段须防止重复热点请求和并发能力查询。
- 当前只有一段自由文本表达状态；“停止投屏”始终可点击，两个尚未实现的无障碍 Back/Home 按钮始终禁用但占据界面，小屏幕没有滚动容器。
- `CastService` 已通过广播发送连接、重试、传输和失败信息，但 Activity 没有把这些事件归并为可驱动控件状态的明确 UI 状态。
- 用户连接设备 WPA2 热点后，App 必须自动识别当前 Wi-Fi，并允许一次点击直接开始投屏，不再要求输入或传递设备热点密码。
- 投屏二维码必须使用 App 原生深链，不能依赖设备热点下无法访问的 HTTPS 落地页。

## 范围内需求

1. 盘点并收敛 Android 端主流程、错误恢复和重复操作，减少无效点击与状态歧义。
2. 将手机 App 操作页整理为清晰的标题、连接状态、设备信息、主要操作和必要辅助说明；不改变既有协议语义。
3. 对权限拒绝、连接失败、服务启动或停止、投屏中断等可恢复状态提供明确反馈和可执行入口。
4. 保持 Android 10+ 兼容，并使用现有原生 Android 技术栈完成改造。
5. 连接检查应幂等；生命周期恢复和用户手动刷新不得叠加热点请求或设备能力查询。
6. 主要按钮必须随当前状态启用、禁用或切换语义；不显示无法执行的占位操作。
7. 页面在常见小屏和横竖屏下可滚动、文案不遮挡，触控目标保持可用。
8. 开始投屏后，主要操作切换为停止；停止、断线、权限拒绝或连接失败后恢复为与当前状态一致的可操作界面。
9. 投屏能力查询和 WebSocket 连接不使用屏幕密码、`X-Setup-Password` 或其他投屏层认证信息，也不传递或持久化热点密码。
10. 设备投屏页二维码使用 `fuckingbms://cast/v1` 深链并携带固定主机和协议版本；Setup Wi-Fi 二维码保持包含 SSID 与 WPA2 密码的标准 `WIFI:` 载荷不变。

## 不在范围内

- 新增投屏协议、BLE 协议或固件侧功能。
- BLE 媒体控制入口、统一功能首页或多页面导航。
- 引入 Compose、Material Components 或其他第三方 UI 依赖。
- 深色主题、主题切换、自定义配色系统，以及投屏内容本身的视觉处理。
- 尚未实现的无障碍 Back/Home 反控按钮。
- 与现有主流程无关的设置系统、账号系统或后台服务重构。

## 验收标准

- [ ] 首次从启动器进入时：未连接 Wi-Fi 则提示连接设备热点；已连接设备热点则自动查询设备能力，用户一次点击即可申请权限并开始投屏。
- [ ] `onCreate`、`onResume` 和用户刷新不会产生重叠的热点请求或能力查询；重复点击连接操作不会叠加请求。
- [ ] 手机 App 操作页清晰显示当前阶段：等待扫码、连接中、查询设备、准备就绪、申请权限、投屏连接/重试、投屏中、已停止或失败。
- [ ] 未就绪时不能开始投屏；投屏未运行时不提供无效停止操作；投屏运行时提供明确的停止入口。
- [ ] 权限拒绝、热点断开、能力查询失败和三次投屏连接失败均给出中文原因及可执行的重试路径，且控件状态同步恢复。
- [ ] 删除未实现的 Back/Home 占位按钮；页面在 Android 10+ 常见横竖屏和小屏尺寸下可滚动，无文案或按钮遮挡。
- [ ] 不新增第三方依赖、Compose、BLE 功能或主题系统；保留协议版本校验，彻底移除投屏层密码认证，Setup AP 自身 WPA2 密码不变。
- [ ] Android 单元测试、debug APK 构建通过；更新后的手机 App 预览图位于根目录 `preview/`。
- [ ] 投屏二维码离线唤起 App；用户手动连接 WPA2 热点后可直接查询设备能力，无需互联网或再次输入密码。
